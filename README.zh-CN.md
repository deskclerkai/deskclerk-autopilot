## 这是什么

**DeskClerk AI Autopilot 是一套可自部署的开源 WhatsApp 私域运营系统。** 它把公司的 WhatsApp 号码变成可管理的客户经营通道：每条会话有负责人，每个客户有档案，每次群发有授权检查，AI 回答有知识库出处，遇到价格、交期、合同、投诉等敏感问题自动转人工。

它只走 **WhatsApp Cloud API** 或官方 **共存模式**，不使用扫码登录、模拟协议等非官方网关。后端是 Python，前端是原生 JavaScript，数据存在自己的 SQLite 里。

## 解决什么问题

| 问题 | 常见现象 | 这套系统怎么解决 |
|---|---|---|
| 客户跟着销售走 | 客户在销售个人手机里，人一走客户就没了 | 号码归公司，客户档案和聊天记录在公司数据库；负责人只是一个字段 |
| 多人共用一个号 | 谁回过、谁没回、谁在跟，全乱 | 共享收件箱、会话分配、负责人、严格回复模式 |
| 线索变冷 | 新线索没人领，老客户很久没人联系 | 公海领取规则、保护期、每日额度、30/90/180 天未联系分层 |
| 重复回复或漏回 | 两个人回同一个客户，或者没人回 | 会话负责人、未读数、筛选、右侧最近沟通 |
| 群发有封号风险 | 导出一批名单就群发，退订的人还在发 | 授权检查、永久退订、已审核模板、24 小时窗口 |
| 老板看不到经营情况 | 只知道“在聊”，不知道回复率、成交、谁在跟 | 12 个看板：负责人、团队、号码、国家、标签、分层、阶段、任务、AI 效果 |
| AI 乱报价、乱承诺 | 通用聊天机器人编价格、编交期 | 知识库出处、相似度阈值、价格/合同/投诉硬拦截、转人工 |
| 员工离职难交接 | 交接靠截图和旧手机 | 客户转移、聊天记录、操作日志都在系统里 |
| 多语言客服排班难 | 阿语、英语、中文无法全天覆盖 | 按语言配置 AI 人设和知识库，答不了转人工 |

## 应用场景

| 场景 | 典型流程 | 系统承担什么 |
|---|---|---|
| **外贸 B2B / 批发** | 展会或官网线索 → 询盘 → 报价 → 样品 → 订单 | 国家/标签分层、负责人分配、跟进分层、公海、成交阶段 |
| **独立站 / DTC** | 广告或网站点击 → WhatsApp 咨询 → 推荐 → 下单 → 售后 | 来源追踪、快速回复、AI 常见问题、价格交期转人工 |
| **展会 / 地推** | 扫码或名片 → 几天内大量新客户 → 后续几周跟进 | 批量导入、按展会打标签、领取额度、保护期、召回分层 |
| **售后 / 质保** | 客户报问题 → 排查 → 换件或维修 | 售后专号、AI 知识库、投诉升级、会话负责人 |
| **教育 / 培训** | 咨询 → 试听 → 报名 → 续报 | 阶段漏斗、顾问归属、按分层跟进、多语言 AI |
| **多品牌 / 多号码** | 多个国家或产品线，各自号码和团队 | 号码 → 接待组 → 人 的权限模型，按号码看看板 |
| **代运营 / 服务商** | 一个客户一套部署，由服务商代管 | 单租户隔离、品牌政策、备份和审计 |

### 外贸 B2B：展会线索不再丢

外贸团队最典型的痛点是：展会收了一堆名片，加到一个 WhatsApp 号上，几周后没人记得谁跟过、问到什么产品、报过什么价。系统把国家、标签、来源、负责人、成交阶段和最后联系时间放在同一张客户卡上，再用“阿联酋 · 30 天没联系”这类分层把该跟进的人圈出来。

### 独立站 / DTC：咨询要快，承诺要准

客户在下单前问尺寸、库存、运费、交期。AI 可以先答标准问题，价格和交期必须转人工；来源字段能看出这个客户是从网站、Instagram、Facebook 还是广告来的，方便复盘哪条渠道真的带来成交。

### 售后 / 质保：重复问题交给 AI，投诉交给人

售后问题重复度高，但投诉、退款、法律话题很敏感。AI 可以引用知识库回答备件、保养、排查步骤；一旦命中投诉关键词或没有知识依据，就带着上下文转给售后负责人。

## AI 能力

这套系统的 AI 不是“接个模型就完事”，而是嵌进 WhatsApp 接待流程里。

| 能力 | 具体做什么 | 为什么重要 |
|---|---|---|
| 知识库 grounding | 每条回答可以带引用的知识条目和相似度 | 客服能看出 AI 为什么这么答，不是黑盒 |
| 置信度阈值 | 最高相似度低于阈值就转人工 | 不确定的答案不硬发 |
| 三种接待方式 | 人工接待 / AI 草稿 / AI 全自动托管 | 可以先草稿跑一周，稳定后再自动 |
| 敏感主题硬拦截 | 价格、折扣、交期承诺、合同、法律、投诉，在调用 AI 前就拦下 | 避免最贵的 AI 错误 |
| 单会话开关 | 某个重要客户可以单独关 AI | VIP、谈判、敏感对话不受影响 |
| 转人工带上下文 | 会话、草稿、引用来源、转人工原因一起保留 | 人工接手不用从头问 |
| 按语言人设 | 阿语、英语、中文分别配置人设、语气、公司介绍、边界 | 一个团队服务多语言客户 |
| AI 客户洞察 | 自动标签、客户摘要、下一步建议、风险提示 | 把聊天内容变成可跟进的销售线索 |
| AI 可观测 | 问题、回答、来源、分数、判断、耗时都落日志；看板看自动率/转人工率 | 能衡量效果，不靠演示 |
| 知识库可替换 | DeskClerk 原生适配，其他知识库可按同一返回结构适配 | 工作流层不被一家锁死 |

### 一次 AI 接待怎么走

```text
客户来信
   │
   ▼
安全拦截 ──► 命中价格/合同/投诉？──► 转人工
   │
   ▼
知识库检索
   │
   ├── 没有依据 / 分数低 ──► 转人工
   │
   └── 有依据的回答
           │
           ├── 人工接待：AI 不动
           ├── AI 草稿：等人确认再发
           └── AI 全自动：直接发出
                     │
                     ▼
              记录来源、分数、判断、耗时
```

### AI 明确不做什么

- 不报价格、不给折扣、不承诺交期；
- 不处理合同、法律、索赔；
- 不在没有知识依据时编答案；
- 不在客户明确要人工时继续自动回复；
- 不把 API Key 写进前端、日志或文档。

## 主要功能

- **会话台**：多号码、共享收件箱、分配、负责人、24 小时窗口、右侧客户档案和最近沟通。
- **客户池**：档案、标签、成交阶段、负责人、授权/退订、CSV 导出、搜索分页。
- **分层**：系统自带活跃/30/90/180 天，自定义按标签、国家、来源、阶段、授权、归属、最后联系组合。
- **公海**：无主客户；退订、已成交、保护期、超范围、每日额度都会拦下。
- **模板与触达**：分层 + 已审核模板；只发有授权、未退订的人。
- **团队与权限**：老板/主管/销售；数据范围、字段级金额、只读账号、只有负责人能回。
- **号码**：多号码、WABA 同步、质量与额度、号码 → 接待组 → 人。
- **看板**：9 个业务筛选维度 + 12 个板块。
- **审计**：登录、分配、领取、放回、设置、AI 变更都有记录。

## 快速开始

要求：Python 3.9+、git。

```bash
git clone https://github.com/jovian6661/deskclerk-autopilot.git
cd deskclerk-autopilot

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

export APP_SECRET="$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')"
./run.sh
```

打开 `http://127.0.0.1:8000`。首次启动会写演示数据：

```text
owner@demo.com    / demo1234
manager@demo.com  / demo1234
agent@demo.com    / demo1234
```

**生产环境不要用演示数据。** 设置 `DEMO_SEED=0`，用 `scripts/create_admin.py` 建第一个老板账号。

Docker：

```bash
cp .env.example .env
# 修改 .env：设置 APP_SECRET 和 APP_ENV=production
docker compose up -d --build
docker compose exec app python /app/scripts/create_admin.py you@company.com 'a-long-password' 'Your Name'
```

## 接入 WhatsApp

1. 在 Meta 创建 App，添加 WhatsApp 产品，绑定企业号码；
2. 在系统 **设置 → 号码管理** 填 WABA ID、Phone Number ID，或从 Meta 同步；
3. 在 **设置 → 集成** 复制 Webhook 地址，填校验 token 和应用密钥；
4. 在 Meta 后台把回调地址设为 `https://你的域名/webhook/whatsapp`，订阅 `messages`；
5. 用另一台手机发一条消息，几秒内应出现在会话台。

详细步骤见 [docs/WhatsApp-账号体系与接入.md](docs/WhatsApp-账号体系与接入.md) 和 [docs/共存接入方案.md](docs/共存接入方案.md)。

## 接入 AI 知识库

1. 在 DeskClerk AI 创建站点和集成 Key；
2. 打开系统 **AI 助手**，填 Base URL、Site ID、API Key；
3. 选人工接待 / AI 草稿 / AI 全自动托管；
4. 用测试提问看命中知识、相似度、判断和耗时。

Key 只存服务端，页面只显示打码值；也可以用环境变量 `AICHAT_KEY`。接入契约见 [docs/AI知识库接入.md](docs/AI知识库接入.md)。

## 安全与合规

- 密码 PBKDF2 加盐，JWT 12 小时过期；
- 只读账号所有写接口 403，不只是隐藏按钮；
- 只有会话负责人能回复，后端硬校验；
- 配了应用密钥就校验 Webhook 签名；
- 未授权不发营销、退订永久排除、24 小时窗口、已审核模板；
- 操作日志覆盖登录、分配、领取、放回、设置、AI 变更；
- 不向维护者发送任何遥测数据。
