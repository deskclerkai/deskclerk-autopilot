# 号码与团队权限（接待组）

> 适用系统：DeskClerk AI Autopilot
> 最后更新：2026-11-09
> 关联文档：[WhatsApp 账号体系](./WhatsApp-账号体系与接入.md)、[员工与客户归属](./员工与客户归属.md)

## 一、为什么不是"一人一个号码"

一人一个号码＝个人号模式：客户锁在个人手里、离职带走、人手一多号码不够用（Meta 一个商业组合初始只有 2 个号，可申请到 20）。

行业通用做法（Chatwoot、respond.io、Zoho TeamInbox、WATI 都一样）是：

```
号码（通道） ──分配──▶ 接待组 ──成员──▶ 人
```

- 一条号码可以给**多个组**看；
- 一个人可以在**多个组**；
- 一个人**不绑定**某一条号码。

## 二、系统里的实现

| 数据 | 表 | 说明 |
|---|---|---|
| 接待组 | `teams` | 组名，如"中东组""售后组" |
| 组成员 | `team_members` | 组 ↔ 人 |
| 号码分配 | `number_teams` | 号码 ↔ 组 |
| 会话来源 | `conversations.number_id` | 这条会话从哪条号码进来 |

判定逻辑（`app/main.py`）：

```python
def allowed_number_ids(user):
    if user["role"] == "owner": return None      # 全部
    teams = team_ids_of(user)                    # 我在哪些组
    return {号码 | 号码被分给了这些组}
```

一个账号能看到的会话 = **会话所在号码 ∈ allowed_number_ids**。

## 三、角色能看到什么

| 角色 | 能看的号码 | 能看的会话 | 能看的客户 |
|---|---|---|---|
| 老板 owner | 全部 | 全部 | 全部 |
| 主管 manager | 本组被分配的号码 | 这些号码上的全部会话 | 本组（按负责人） |
| 销售 agent | 本组被分配的号码 | 这些号码上的全部会话 | 只有自己名下 + 公海 |

注意：**销售现在能看到同组号码上的全部会话**（共享收件箱），不再只看自己那几条。想只看自己的，用会话台顶部的「我的」标签。

## 四、设置在哪

设置 → **号码与团队**，一张看板分上下两块：

```
上：号码 × 组（打勾 = 这个组能看这条号）
        中东组   售后组
UAE 号    ☑       ☐
Support   ☐       ☑
非洲号    ☑       ☐

下：组 × 人（打勾 = 这个人在这个组）
        老板 主管 王杰 陈宇
中东组   ☑    ☑    ☑   ☐
售后组   ☑    ☐    ☐   ☑
```

- 新建组：输入名称点「＋ 新建组」。
- 删除组：只解除组员和号码分配，**不删人、不删号码**。
- 改动立即生效：被移出组的销售，下次刷新就看不到那条号的会话了。

## 五、和"客户归属"的关系

两个维度，互不替代：

| | 号码权限 | 客户归属（负责人） |
|---|---|---|
| 决定 | 你能看到哪条通道的**会话** | 这条**客户记录**归谁跟 |
| 范围 | 组 | 个人 |
| 例子 | 中东组都能看 UAE 号的会话 | UAE 号上某个客户归王杰，别人看不到他的档案 |

后续如果要做"客户也按号码隔离"，需要给客户补 `number_id` 并改 `visible_contacts()`；本期未做。

## 六、接口

| 接口 | 说明 | 权限 |
|---|---|---|
| `GET /api/teams` | 组列表（含 members / numbers） | 登录 |
| `POST /api/teams` | 新建组 `{name}` | 老板 |
| `PATCH /api/teams/{id}` | 改名 `{name}` | 老板 |
| `DELETE /api/teams/{id}` | 删组（解除关联） | 老板 |
| `POST /api/teams/{id}/members` | 覆盖组成员 `{user_ids:[...]}` | 老板 |
| `POST /api/numbers/{id}/teams` | 覆盖号码分配的组 `{team_ids:[...]}` | 老板 |
| `GET /api/numbers/allowed` | 当前账号能看的号码（会话台筛选用） | 登录 |
| `GET /api/conversations` | 已按号码权限过滤 | 登录 |

取消息、发消息、模拟来消息、分配会话，都会校验 `can_see_conv()`：不属于自己号码的会话返回 403。

## 六点五、谁能回复（强制模式）

设置 → 号码与团队 → 最上方「谁能回复」，两种模式：

| 模式 | 规则 |
|---|---|
| **只有负责人能回复（默认，推荐）** | 一条会话只有 `owner_id` 指向的人能发消息；其他人能看到（如果在同组号码上），但输入框显示"归 X 负责，只有 TA 能回复" |
| 组内谁都能回复 | 同组号码上的任何人都能回（传统共享收件箱） |

未分配的会话：显示「认领」按钮，谁先认领归谁，认领后才能回。
主管/老板要回复别人的会话：先用「分配给…」转给自己，再回复。

后端是硬校验：`send_message` 检查 `cv.owner_id == user.id`，否则返回 `403 not_owner`；只读账号返回 `403 read_only`。前端只是提示，绕不过接口。

## 六点六、会话可见范围（公司层面开关）

设置 → 号码与团队 → 「会话可见范围（全公司统一）」：

| 模式 | 谁设 | 销售能看到 | 主管/老板 |
|---|---|---|---|
| **组内共享（默认）** | 只有老板 | 本组号码上的全部会话（能看不能回别人的） | 全部 |
| **只看自己的** | 只有老板 | 分给自己的 + 未分配的（未分配可认领） | 全部 |

三条要点：

1. **只有老板能改**，这是公司层面的权限，员工不能自己开。
2. 默认是**组内共享**——销售能看到同事的聊天内容，但**只有负责人能回复**（回复限制是另一项设置）。
3. 选"只看自己的"后，销售看不到同事的会话；主管和老板仍然看全部，否则没法管理。

两个设置互不替代：

| 设置 | 管什么 |
|---|---|
| 回复权限（`inbox.reply_owner_only`） | 能不能**发消息** |
| 可见范围（`inbox.visibility`） | 能不能**看到会话** |

## 七、边界

- 组管理员（主管）目前**不能**自己改组配置，只有老板能改。
- 一个组没有分配号码 → 组里的人打开会话台是空的，这是按设计，不是 bug。
- 号码删除时不会自动清理 `number_teams` 记录（残留无害，号码 ID 不复用）。
- 接待组与"团队与权限"里的 `users.team`（老字段）是两套东西：老字段只影响客户可见范围，新的组影响会话可见范围。
