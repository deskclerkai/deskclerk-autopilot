## 一、三层结构

```
Meta 企业账户 Business Portfolio        ← 营业执照认证，合同主体
      └── WABA（WhatsApp Business Account）   ← 号码容器
            ├── 号码 A：+971 中东销售
            ├── 号码 B：+86  售后客服
            └── 号码 C：+212 非洲销售
```

| 层级 | 作用 | 谁持有 |
|---|---|---|
| 企业账户 | 认证主体、计费、审核 | 公司 |
| WABA | 装号码的容器，模板、质量评级都挂在它下面 | 公司 |
| 号码 | 客户实际看到的号 | 公司 |

**默认 2 个号码，可申请增加**；每个号码有独立的 `phone_number_id`、质量评级、每日限额。

## 二、三种 WhatsApp，别混

| 类型 | 谁用 | 能不能接后台 |
|---|---|---|
| 个人版 WhatsApp | 个人 | 不能，禁止用于商业系统 |
| Business App | 小商家，手机上一个 App | 一般不能；符合条件可走 **Coexistence** 共存 |
| **Business Platform（Cloud API）** | 企业系统 | **能，这就是我们要用的** |

### 共存模式（Coexistence）
同一个符合资格的 Business 号，**手机上继续用，同时接到后台**。适合已经有大量客户在 Business App 上的企业。

**通俗解释 Coexistence（共存）**：

- "手机 App"指 **WhatsApp Business**——绿色 WhatsApp 的商业版，装在老板/销售的手机上，能填公司资料、设自动回复。
- 平时客户发消息，手机响；接了 Cloud API 之后，这个号就不能再装那个 App。
- Coexistence 是 Meta 给的一座"桥"：**同一个号码，手机上的商业版 App 照常用，同时这个号也接到我们的系统**。
  - 客户发一条 → 手机 App 和我们系统**都能看到**；
  - 员工在系统里回 → 手机 App 里也显示这条已发出；
  - 反过来在手机 App 里回，系统里也能看到。
- 代价：每 14 天要用手机打开一次 App；群聊不同步；广播列表停用；不能编辑/撤回消息；通话、目录、状态这些 API 不支持。
限制：需 Meta 资格审核、必须走官方 Embedded Signup、历史消息同步有限。

## 三、销售怎么工作（关键）

**销售不需要 WhatsApp 账号。**

1. 销售用**我们系统**的账号登录
2. 客户消息经 Cloud API 进入系统
3. 系统按「负责人」字段决定这条消息归谁
4. 销售在系统里回复，由**公司号码**发出
5. 客户看到的永远是公司号，不知道背后是谁

> 区别于企业微信：企微是"员工各有账号"，WhatsApp 是"号码归公司，员工没有 WA 账号"。
> 所以公海、转交、离职交接都能做——变的只是系统里的字段。

---

## 四、为什么这是公海模式的前提

公海本质是**改负责人字段**，客户侧无感知。
成立的前提只有一个：**号码归公司**。

若销售各用私人号加客户，则客户属于个人，公海不成立，也无法交接。
这也是必须做「企业号 + 多号统一接入」的根本原因。

**代价**：私人号上的老客户搬不过来（WhatsApp 不支持转移联系人），只能让客户主动加公司号。

## 五、系统对应字段

| 系统位置 | 字段 | 说明 |
|---|---|---|
| 设置 → 号码管理 | `label` / `phone` | 内部名称与号码 |
| 同上 | `waba_id` / `phone_number_id` | Meta 提供，填入后才能真实收发 |
| 同上 | `quality` / `daily_limit` / `sent_today` | 质量评级与限额，用于发送排队 |
| 同上 | `status` | connected / cooling / disconnected |

**未填 waba_id 与 phone_number_id 的号码处于沙盒**：能建任务、能计数，不真实发送。

## 六、接入步骤

1. 建 Meta Business Portfolio，完成企业认证
2. 建 WABA
3. 添加号码（每个业务线/地区一个），完成号码验证
4. 提交展示名（Display Name）审核
5. 申请 Cloud API：拿 `access token` + `phone_number_id`
6. 填进系统「号码管理」
7. 提交消息模板审核（Marketing / Utility 分类）
8. 用测试号跑通收发，再切生产

## 七、硬约束与风险

1. **一号不能两处挂**：注册到 Cloud API 后，不能同时装在手机上双开（Coexistence 例外）。
2. **联系人不能转移**：号与号之间不能搬客户。
3. **号码要公司能控制**：能长期收验证码，不用销售个人号。
4. **模板必须审核**：改一个字重新审；分类错会被拒。
5. **先授权后营销**：未 opt-in 发营销模板是封号首因。
6. **24 小时窗口**：客户最后一条消息后 24 小时内可自由回复，超出只能用模板。

## 八、号码管理 vs 团队与权限：到底有什么区别

这两个页面管的是**完全不同的两样东西**，不会冲突：

| | 号码管理（Numbers） | 团队与权限（Team） |
|---|---|---|
| 管什么 | 公司有几条 WhatsApp 收发通道 | 有几个人能登录后台 |
| 一条记录代表 | 一个公司号码（WABA + Phone Number ID） | 一个员工账号（邮箱 + 密码 + 角色） |
| 从哪来 | Meta 后台 / Graph API | 在系统里自己建 |
| 一个能对多个吗 | **能**：一个号码可以由很多员工一起接待 | **能**：一个员工可以用多个号码接待 |
| 删掉会怎样 | 该号码不再收发；历史消息还在库里 | 该员工不能登录；名下客户要转走 |

一句话：**号码是"门"，团队是"人"**。门不需要跟人绑定；企业完全可以让 3 个销售共用同一条 UAE 号码，也可以让一个人同时看 UAE 和沙特两条号。

### 真正添加/同步的是什么

- **手动添加**：填公司 WhatsApp 号码 + Meta 给的 WABA ID、Phone Number ID。适用于号码少、想自己控制。
- **从 Meta 同步**：在「号码管理」点「⟳ 从 Meta 同步」，填 WABA ID 与 access token，系统调 Graph API 的
  `GET /{WABA_ID}/phone_numbers`，把这个 WABA 下所有号码一次拉过来（带显示名与质量评级）。
  - 号码是 **Meta 那边先有的**，系统只能拉、不能凭空创建；
  - 需要 token 有该 WABA 的 `whatsapp_business_management` 权限；
  - token 存在服务端，页面上只显示打码。
- **不会同步的**：员工名单。Meta 不提供"员工列表"接口，员工只能在「团队与权限」里自己建。

### 系统里的落地：号码与团队

具体到"哪条号给哪个组看"，已经做成一张看板：设置 → 号码与团队，号码 × 组、组 × 人两片勾选矩阵。
规则与接口见 [号码与团队权限](./号码与团队权限.md)。

### 建议的分配方式（企业用法）

| 场景 | 做法 |
|---|---|
| 一条号，多人接待 | 号码建一次；团队里建多个销售；客户按负责人分配 |
| 多条号按地区分 | 每条号起名叫「UAE sales」「Saudi support」；销售按地区领取公海客户 |
| 销售离职 | 停用账号 + 转移客户；号码不动 |
