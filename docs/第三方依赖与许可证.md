# 第三方依赖与开源合规

> 产品：DeskClerk AI Autopilot
> 最后更新：2026-11-12
> 用途：开源前的依赖盘点、许可证核对、品牌与商标说明

## 一、结论先说

1. **没有使用任何"别人的类似项目"的代码。** 系统后端（FastAPI 路由、SQLite 数据层、权限、AI 连接器）、前端（原生 JS/CSS）、测试脚本，都是为本项目编写的。
2. **没有引入 Chatwoot、Typebot、n8n、Dify、Evolution API、WAHA、Baileys、WPPConnect 等项目的代码或 SDK。**
3. 只使用了 4 个通用基础库（FastAPI、Uvicorn、PyJWT、requests），都是宽松许可证，允许商用、允许闭源、也允许再开源。
4. 前端没有 CDN、没有第三方 UI 框架、没有外部字体文件、没有图标库；图表是手写 SVG，图标是 Unicode 字符。
5. 唯一的外部服务是 DeskClerk 知识库 API —— 那是**服务**，不是代码，不受开源许可证约束，但受服务条款约束。

### 许可证义务

- **MIT / BSD**：保留版权与许可证声明即可，可商用、可闭源、可再开源。
- **Apache-2.0（requests）**：分发时需要保留许可证与 NOTICE（如果上游提供 NOTICE），并说明修改过的文件。
- 没有 GPL / AGPL / SSPL 依赖，不存在"必须开源整个项目"的传染性义务。

## 五、如果决定开源，建议这样做

### 1. 选许可证

| 方案 | 适合 | 说明 |
|---|---|---|
| **MIT** | 想让人随便用、传播最快 | 最短、最宽松；别人可以闭源商用 |
| **Apache-2.0** | 想保留专利授权与 NOTICE | 比 MIT 多一条专利授权，企业更放心 |
| **AGPL-3.0** | 想强制衍生品也开源 | 有传染性，多数 SaaS 客户会避开 |

建议：**Apache-2.0**。理由是项目会接第三方 API、未来可能有企业客户，专利条款更稳。

### 2. 需要补的文件

- `LICENSE`（放仓库根目录）
- `NOTICE`（如果用 Apache-2.0，列出 requests 等 Apache 依赖）
- `THIRD_PARTY_NOTICES.md`（可直接用本文档第二、三节）
- `README` 里加"License"一节

### 3. 品牌与商标

- **DeskClerk / DeskClerk AI / DeskClerk AI Autopilot** 是你们自己的品牌；
- 代码许可证**不自动授予商标使用权**，别人可以复用代码，但不能用 DeskClerk 名字做自己的产品；
- 如果公开仓库，建议在 README 写明："Code is licensed under Apache-2.0. The DeskClerk name and logo are trademarks of the owner and are not covered by the code license."

### 4. 不要带出去的东西

- 真实 API Key、`.env`、数据库文件（`data/app.db`）；
- 客户名单、手机号、聊天记录；
- 演示账号密码（`demo1234`）；
- 你们内部的知识库文档原文。

建议在开源前：
1. 把 `data/` 加入 `.gitignore`；
2. 换掉演示账号密码；
3. 把 `AICHAT_KEY` 等全部改成环境变量；
4. 用示例数据重新生成一份演示库。

## 六、关于"别人的类似开源项目"

我们**没有**把 Chatwoot / Typebot / n8n / Dify / Evolution API 的代码拿进来，也没有基于它们改。

只做了两件事：

1. 读它们的公开文档，理解行业做法（会话台、分配、转人工、知识库）；
2. 自己实现。

所以不存在"需要去掉别人代码"的问题。如果以后要引入某个开源组件，先看许可证：

- MIT / BSD / Apache-2.0：可用；
- GPL / AGPL / SSPL：谨慎，可能要求整个项目开源；
- 非官方 WhatsApp 网关（Baileys、WPPConnect、Evolution、WAHA）：**不要用**，违反 WhatsApp 条款，封号风险高。
