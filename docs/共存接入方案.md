# 共存模式接入方案（销售用系统 + 老板手机旁观）

> 适用系统：DeskClerk AI Autopilot
> 最后更新：2026-11-09
> 关联文档：[WhatsApp 账号体系](./WhatsApp-账号体系与接入.md)、[号码与团队权限](./号码与团队权限.md)

## 一、目标组合

| 谁 | 在哪工作 | 能做什么 |
|---|---|---|
| 销售 | **只用我们的系统** | 看分配给自己/本组的会话，只有负责人能回复 |
| 主管 | 我们的系统 | 分配、看本组数据、转客户 |
| 老板 | 我们的系统 + **手机 WhatsApp Business** | 系统里看全部；手机上随时旁观全部聊天 |

关键取舍：**共存让手机 App 看到全部聊天，这是 Meta 的固有特性，关不掉。**
所以手机只发给老板/主管，不给一线销售；销售的分工和回复限制全部由我们系统承担。

```
客户 ⇄ 公司 WhatsApp 号
         ├── Cloud API ⇄ 我们的系统（销售回复 / 分配 / 统计）
         └── WhatsApp Business App（老板手机：旁观，偶尔回）
                    ↑ 消息经 webhook 双向同步
```

## 二、Meta 侧前置条件（必须全部满足）

| 条件 | 说明 |
|---|---|
| 号码状态 | 现在在 **WhatsApp Business App** 上，且**从未被任何 WABA 接过** |
| App 版本 | 2.24.17 或以上 |
| 企业认证 | Meta Business 账户完成企业验证 |
| 国家 | 尼日利亚、南非不支持共存 |
| Embedded Signup | 必须用 **v4**（v2/v3 于 2026-10-15 下线） |
| 保持在线 | 每 14 天用手机打开一次 App，否则连接断开 |

⚠️ 顺序不可逆：号码一旦以普通 Cloud API 接入，就不能再回头做共存。

## 三、接入步骤

1. 确认每个号码的状态（是否在 App、是否被接过），列成清单。
2. 完成 Meta Business 企业认证。
3. 创建 Meta App，添加 WhatsApp 产品。
4. 配置 Embedded Signup v4，选择 coexistence 流程。
5. 号码授权给我们的应用（`whatsapp_business_management` + `whatsapp_business_messaging`）。
6. 配置 webhook：回调地址 `https://<域名>/api/webhooks/whatsapp`，填入 verify token，订阅 `messages` 与 `smb_message_echoes`。
   - 强烈建议同时填 `app_secret`：填了之后回调会校验 `X-Hub-Signature-256`，伪造请求一律 403；不填则只靠 URL 保密。
7. 在 设置 → 号码管理：填 WABA ID、Phone Number ID、Access Token，接入方式选「共存」。
8. 联调：客户发 → 系统收到；系统发 → 手机看到；手机发 → 系统收到并标记「手机 App 回复」。

## 四、系统侧已完成 / 待做

### 已完成（本轮）

| 能力 | 说明 |
|---|---|
| 号码接入方式 | `numbers.access_mode`：沙盒 / Cloud API / 共存，号码管理页可选 |
| Webhook 校验 | `GET /api/webhooks/whatsapp` 按 verify token 返回 challenge |
| 收信 | `POST /api/webhooks/whatsapp` 解析客户消息，自动建客户/会话 |
| 共存回显 | 解析 `smb_message_echoes`（手机 App 发出的消息），入库并标 `via='app'` |
| 去重 | 按 `wa_message_id` 去重，重复推送不重复入库 |
| 退订识别 | 客户回 STOP / 退订 等关键词自动标记 |
| 校验测试 | 本地已用模拟 payload 验证：收信 + 回显 + 去重全部通过 |

### 待做（需要真实 Meta 凭证）

| 能力 | 为什么现在做不了 |
|---|---|
| 真实发送 | 当前是沙盒，发送只入库 |
| 模板发送 | 需要已审模板 + token |
| 送达/已读回执 | 需要 `statuses` webhook |
| 图片/文件消息 | 需要媒体上传/下载接口 |
| 历史聊天导入 | 共存接入后 24 小时内同步，需真实号码 |
| 14 天提醒 | 需要记录 App 活跃时间（可由 webhook 回显推断） |

## 五、权限与规则

- 销售：无手机 App 权限；系统里只有负责人能回复（严格模式已上线）。
- 老板：手机 App 能看到全部。**在 App 里回的消息不经过我们接口**，因此不受"负责人"限制，但会以「手机 App 回复」入库，可审计。
- 建议：老板把手机 App 当"随身查看器"，实际回复尽量在系统里做，避免和销售撞车。

## 六、风险清单

| 风险 | 应对 |
|---|---|
| 手机 App 谁拿到都能看全部 | 只给老板/主管，不发给销售 |
| 手机回复绕过负责人限制 | 标记 `via=app`，操作日志可查；制度上要求老板少用 |
| 14 天不开 App 连接断开 | 给老板设日历提醒；系统后续可加倒计时提示 |
| 群聊、广播、编辑撤回不可用 | 业务上不用这些功能，或保留一个非共存号码做群 |
| 迁移期消息可能丢 | 接入前做好备份与公告，选低峰时段 |

## 七、验收清单

- [ ] 每个号码状态确认完毕（干净、在 App、未被接）
- [ ] Meta 企业认证通过
- [ ] Embedded Signup v4 配置完成
- [ ] webhook 校验通过
- [ ] 客户发消息，系统 5 秒内出现

- [ ] 老板手机 App 发消息，系统出现并标「手机 App 回复」
- [ ] 重复回调不重复入库
- [ ] 只读账号无法发送；非负责人无法发送
- [ ] 退订关键词自动拉黑
- [ ] 14 天提醒已设置
