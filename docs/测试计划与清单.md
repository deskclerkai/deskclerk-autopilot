# 测试计划与清单

> 项目：DeskClerk AI Autopilot
> 版本：v1.0（2026-11-10）
> 适用：每次改动后、每次交付前

## 一、测试原则

1. **自动化优先**：能写成断言的，不靠手工点。
2. **独立数据库**：功能/边界/界面测试各用独立库，绝不碰演示库。
3. **全量回归**：改任何一处，五套测试全跑，不挑着跑。
4. **bug 必转用例**：每修一个 bug，必须补一条对应断言，防止复发。
5. **外部依赖单独标记**：需要 Meta/SMTP/支付的，列为「阻塞项」，不算通过。

## 二、一键执行（两档，不用每次都全跑）

| 场景 | 命令 | 跑什么 | 实测耗时 |
|---|---|---|---|
| **日常小改**（调样式、改文案、加一个小功能） | `./scripts/run_all_tests.sh --quick` | 接口回归 151 项 + 冒烟（全部页面渲染/JS 报错） | **约 30 秒** |
| **交付前 / 动了权限、数据、数据库** | `./scripts/run_all_tests.sh --full` | 接口 + 模糊 + 边界安全性能 + 界面点击 + 冒烟 | **约 90 秒** |

两档都会：起临时服务（7850–7853）→ 用全新数据库 → 跑完自动关服务，不碰你的演示库。
失败返回非 0。

建议节奏：

- 开发过程中：改一点跑一次 `--quick`；
- 功能做完、准备给别人看：跑一次 `--full`；
- 修改了权限、会话、回收、数据库结构：**直接 `--full`**，不要省。

## 四、验收标准

一次交付必须同时满足：

1. 五套自动化测试全部通过；
2. 本清单里所有 ✅ 项保持通过；
3. 🟡 项在交付说明里写明"手工验过/未验"；
4. ⛔ 项明确写"缺什么条件"，不能含糊过关。

## 五、已知测试缺口

- 没有单元测试（当前是接口级 + UI 级，足够覆盖业务，但重构时粒度偏粗）。
- 只有 Chrome 内核自动化，Safari/Firefox 未自动测。
- 老库迁移只有代码逻辑，没有拿真实旧库样本跑过。
- Docker/HTTPS 只能上服务器验。
- 真实 WhatsApp 全链路必须等 Meta 凭证。

## 六、缺陷处理流程

1. 发现 → 记入 issue 跟踪（现象、复现步骤、影响）。
2. 修复 → 在对应测试脚本里补一条断言。
3. 全量跑 `./scripts/run_all_tests.sh`。
4. 通过后同步更新 `docs/` 对应正式文档。
