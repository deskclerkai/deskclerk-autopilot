# 公海机制（客户公海 / Public Pool）

> 适用系统：DeskClerk AI Autopilot
> 最后更新：2026-11-09
> 关联文档：[WhatsApp 账号体系与接入](./WhatsApp-账号体系与接入.md)

## 一、公海是什么

**公海 = 没有负责人的客户集合。**

- 客户有负责人（owner）→ 归这个销售跟进，别人看不到、也领不走。
- 客户没有负责人（owner 为空）→ 待在公海，符合规则的人可以领走。

公海不是"客户池"的另一个名字：客户池（Contacts）是**全量客户**，公海是其中**无主**的那一部分。

## 二、为什么 WhatsApp 一对一的客户也能进公海

关键前提：**WhatsApp 号码属于公司，不属于销售个人。**

客户是加在"公司的 WhatsApp 商业号"上的，销售只是登录我们的系统去回复。所以换销售、离职、转组，客户不会跟着人走——这正是公海能成立的原因。详见 [WhatsApp 账号体系与接入](./WhatsApp-账号体系与接入.md)。

反过来说：如果号码是员工自己的手机号，客户就锁在那个人手里，公海无从谈起。

## 三、客户怎么进公海

| 入口 | 触发条件 |
|---|---|
| 新线索没分配 | 建客户时不填负责人（如官网表单、广告线索未指派） |
| 销售主动放回 | 客户档案里点「放回公海」 |
| 超期自动回收 | 有负责人，但超过 N 天（默认 90 天）没联系 |
| 离职交接 | 删除/停用成员前把客户转出，未处理的落到公海 |

自动回收在服务启动时执行一次，也可以在 设置 → 公海规则 里点「立即执行回收」。

## 四、不是每个都能领 —— 五条规则

公海页面每行的右侧只有两种结果：**「领取」按钮**，或者**一个说明为什么不能领的标签**。

| 状态 | 标签 | 规则 | 能不能改 |
|---|---|---|---|
| 可领取 | 领取按钮 | 满足下面全部条件 | — |
| 已退订 | 已退订 | `opt_out = 1`，客户明确说过 STOP / 退订 | 不可改。合规红线 |
| 已成交 | 已成交 | 成交状态属于成功态（已成交/已签约/在读…） | 关掉「成交客户不回收」才可能进池 |
| 保护期 | 保护期 | 刚被放回公海，N 小时内（默认 24）别人不能抢 | 改「退回后保护几小时」 |
| 超范围 | 超范围 | 客户身上的标签，不在该销售的领取范围内 | 改 设置 → 领取范围 |
| 已被领 | 已被领 | 别人先领走了，刷新后即消失 | — |

**为什么要这五条**：如果每行都能点「领取」，销售会闭眼乱领、把退订客户领回去再发消息（直接封号）、把已经成交的客户重复跟。公海的价值是"把对的人分给对的人"，不是"谁手快谁拿"。

## 五、保护期（防抢单）

销售 A 把客户放回公海，可能是觉得线索质量不对，但这不代表销售 B 可以立刻拿走同一个客户去重复打扰。

规则：客户被「放回公海」后，`released_at` 记录时间；在 `protect_hours`（默认 24 小时）内，任何人都不能领取，页面上显示「保护期」。

- 自然回收（超期未联系）**不设**保护期——那种情况本来就该换人跟。
- 保护期只针对"人主动放回"。

## 六、领取范围（按标签划人）

设置 → 公海规则 → **领取范围**，给每个销售勾选允许领取的标签。

- 一个标签都不勾 = 不限制，什么都能领。
- 勾了标签 = 客户身上**至少有一个**该标签，才能领（标签之间是"或"的关系）。
- 只对销售（agent）生效；老板、主管不受限制。
- 客户没有标签时，有范围的销售领不到（页面上显示「超范围」）。

适用场景：中东线销售只领「中东」标签的客户；做汽配的只领「Auto parts」；新人不给范围，先练手。

## 七、筛选与排序

公海页面顶部有三组筛选，全部是实时统计，数字跟随当前池子变化：

| 筛选 | 说明 |
|---|---|
| 按标签 | 标签后面显示「池内总数 · 可领 N」。没有"可领"字样的说明该类全部可领 |
| 按国家 | 从池内客户的国家自动生成，不做固定列表 |
| 排序 | 最久未联系（默认，优先处理冷线索）/ 最近联系 |
| 搜索 | 姓名、号码、国家，随打随筛 |

筛选可以叠加：标签 + 国家 + 搜索同时生效。

## 八、领取额度（防囤客）

- 每个销售每天最多领 `daily_claim_limit` 个（默认 10），老板不受限。
- 按"自然日"重置，计数依据操作日志里当天的 `claim` 记录。
- 额度用完，页面顶部 KPI 会显示 `10 / 10`，再点领取会被拦下并提示。

额度是防囤客的闸门：设太高销售会囤一堆跟不过来，设太低好线索没人领。10 个/天是常见起步值。

## 九、设置项与默认值

| 设置项 | 默认 | 含义 |
|---|---|---|
| 多少天没联系就回收 | 90 | 有负责人的客户，超期自动回公海 |
| 每人每天最多领几个 | 10 | 销售领取额度 |
| 退回后保护几小时 | 24 | 主动放回后的锁定期 |
| 成交客户不回收 | 开 | 成功态客户不进公海、不被自动回收 |
| 自动回收 | 开 | 服务启动时执行一次 |
| 领取范围 | 空 | 按销售配置可领标签 |

存储位置：`settings` 表中 `key = "pool"` 的 JSON，形如：

```json
{
  "recycle_days": 90,
  "daily_claim_limit": 10,
  "protect_hours": 24,
  "exclude_success": true,
  "enabled": true,
  "scopes": { "3": [1, 4] }
}
```

`scopes` 的键是用户 ID（字符串），值是该销售可领的标签 ID 列表；`{}` 表示不限制。

## 十、接口

| 接口 | 作用 |
|---|---|
| `GET /api/contacts?view=pool&tag=&country=&sort=&kw=` | 公海列表，每条带 `claimable` / `claim_block` |
| `GET /api/pool/stats` | 池内总数、可领数、各拦截原因计数、我的今日额度 |
| `GET /api/pool/facets` | 标签 / 国家分面，每项带池内总数与可领数 |
| `POST /api/contacts/{id}/claim` | 领取（被规则拦下时返回 `400 blocked:<原因>`） |
| `POST /api/contacts/{id}/release` | 放回公海（写入 `released_at`，进入保护期） |
| `POST /api/pool/recycle` | 立即执行一次自动回收 |

拦截原因取值：`opted_out` / `success` / `protected` / `out_of_scope` / `owned`。

## 十一、明确不做的事

- **不做自动分配**：系统不会按负载或规则自动把客户塞给某个销售，分配永远是人点「领取」或主管手动指派。
- **不做"抢单排行"**：公海不是抢单游戏，看板统计的是成交，不是领取数量。
- **不做跨号码转移**：客户属于某个 WhatsApp 号码，不能把这个号码上的客户转到另一个号码的公海里去（Meta 侧不允许），详见账号体系文档的硬约束。
