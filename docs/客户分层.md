# 客户分层（Segments）

> 适用系统：DeskClerk AI Autopilot
> 最后更新：2026-11-09
> 关联文档：[客户池与筛选](./客户池与筛选.md)、[公海机制](./公海机制.md)

## 一、分层和标签的区别

| | 标签 Tags | 分层 Segments |
|---|---|---|
| 怎么来 | **人手动打**，一个客户可以有很多个 | **按规则自动算**，不存名单 |
| 例子 | 汽配、广交会、问过价 | 90 天没联系、阿联酋 · 已授权 |
| 会不会变 | 只有人改才变 | 每次打开页面重新计算，客户行为一变就变 |
| 用来干嘛 | 描述客户是谁 | 圈出"这批人该做一件事" |

两者配合：分层规则里可以直接选标签（"带汽配标签、且在公海"）。

## 二、系统自带的分层（只读）

| 分层 | 规则 | 说明 |
|---|---|---|
| Active | 最后联系在 30 天内 | 还在热乎的客户 |
| Dormant 30d | 最后联系 30–89 天 | 开始变冷 |
| Dormant 90d | 最后联系 90–179 天 | 该做召回了 |
| Dormant 180d | 180 天以上没联系 | 基本沉睡 |

已退订的客户不算进活跃层（`segment_of()` 先判退订）。

## 三、自定义分层

老板、主管可以在 客户分层 页点「＋ 新建分层」自己定规则。

### 可选条件

| 条件 | 说明 | 多选时 |
|---|---|---|
| 标签 | 客户身上有这些标签 | 任选一个即命中（OR） |
| 国家 | 客户所在国家 | OR |
| 来源 | Website / Facebook / Instagram / Ads 等 | OR |
| 成交状态 | 线索 / 已联系 / 谈判中 / 已成交 … 随行业预设变化 | OR |
| 授权 | 只要已授权 / 只要已退订 / 不限 | — |
| 归属 | 只在公海 / 已有负责人 / 不限 | — |
| 最后联系 | 超过 N 天没联系 / N 天内联系过 | — |

**不同条件之间是 AND**：比如"国家＝UAE"且"最后联系超过 30 天"且"只要已授权"，三个都满足才进这一层。

### 看板指标

选中一个分层后，右侧显示：

| 指标 | 含义 |
|---|---|
| 命中 | 这一层有多少人 |
| 可发送 | 其中有有效授权、可以发营销消息的人 |
| 已退订 | 命中里退订的人数（发送时自动排除） |
| 已成交 | 命中里成交状态属于成功态的人数 |
| 成交金额 | 命中客户的成交金额合计（销售看不到金额时按权限隐藏） |
| 这一层里都有谁 | 前 300 人，带负责人、标签、成交状态、最后联系 |

「去客户池看」会把这些客户带到客户池，并保留分层筛选。

## 四、规则是怎么存的

`segments.rule` 是一段 JSON。系统自带的存 `{"type": "active"}`；自定义的存条件对象：

```json
{
  "tags": [1, 4],
  "countries": ["UAE", "Saudi Arabia"],
  "sources": ["Website"],
  "deal_status": ["Lead", "Contacted"],
  "opt": "in",
  "pool": "in",
  "last_contact": { "op": "gte", "days": 30 }
}
```

- 空字段 = 不参与筛选。
- `opt`：`in` / `out` / 不写＝不限。
- `pool`：`in`＝只在公海、`owned`＝已有负责人、不写＝不限。
- `last_contact.op`：`gte`＝超过 N 天没联系；`lte`＝N 天内联系过。
- `created` 同样是 `{op, days}`，按加入时间算（接口支持，界面暂未开放）。

## 五、接口

| 接口 | 说明 | 权限 |
|---|---|---|
| `GET /api/segments` | 全部分层 + 命中/可发送/退订/成交/金额 | 登录即可 |
| `GET /api/segments/facets` | 新建分层可选的标签、国家、来源、成交状态 | 登录即可 |
| `POST /api/segments` | 新建 `{name, rule}` | 老板 / 主管 |
| `PATCH /api/segments/{id}` | 改名或改规则（仅自定义） | 老板 / 主管 |
| `DELETE /api/segments/{id}` | 删除（仅自定义，且没被触达任务引用） | 老板 / 主管 |
| `GET /api/segments/{id}/contacts` | 这一层的客户名单 | 登录即可 |

## 六、边界

- 分层**不存名单**，只存规则。所以客户状态一变，分层跟着变，不需要"刷新名单"。
- 删除分层不影响客户，也不影响标签。
- 已经被触达任务引用的分层不能删（会先报错）。
- 系统自带的 4 层不能改名、不能删。
